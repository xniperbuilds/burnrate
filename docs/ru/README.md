# burnrate

**Выясните, что на самом деле сжигает токены вашего кодового агента — измерено по вашим собственным сессиям, а не маркетинговый процент.**

Каждый скилл для экономии токенов обещает цифру. `экономит 65%`. `счёт ниже примерно на 31%`. Эти цифры получены из чужих сессий, с чужими файлами и чужими привычками. Они не ваши, и проверить их вы не можете.

Так проверьте свои. Одна команда, без установки, без API-ключа, без сети:

```bash
python burnrate.py --all
```

---

## То, что никто не измеряет

Вот реальный корпус из 348 сессий — 36 000 ходов модели, 8,8 миллиарда токенов:

| | сырые токены | доля | доля с учётом стоимости |
|---|---:|---:|---:|
| **контекст, пересылаемый на каждом ходу** (cache read) | 8 310 254 792 | **94,2%** | 49,6% |
| записанный контекст (cache write) | 446 493 285 | 5,1% | 33,3% |
| **вывод — то, что пишет агент** | 54 477 459 | **0,6%** | 16,3% |
| ввод (без кэша) | 13 730 167 | 0,2% | 0,8% |

**Контекст: 99,2% сырых токенов, 82,9% с учётом стоимости. Вывод: 0,6% сырых, 16,3% взвешенных.**

Медианная сессия пересылала контекста в **109 раз больше**, чем писала. Из 348 сессий лишь **5** написали больше, чем перечитали.

Любой скилл, экономящий токены за счёт сокращения ответов, выбрасывания артиклей или речи «как пещерный человек», оптимизирует эти **0,6%**. Даже с поправкой на более высокую цену выходных токенов он метит в самую маленькую из четырёх статей — и при этом добавляет собственные инструкции в контекст, который пересылается на каждом ходу. Навсегда.

Именно поэтому экономия так и не появляется.

*(Показаны обе доли, потому что они рассказывают разные истории. Сырая — это то, что заполняет ваше окно контекста; взвешенная использует опубликованные коэффициенты тарификации: cache write 1,25×, cache read 0,10×, вывод 5× от ввода. Цитировать только удобную — это и есть проблема, а не решение.)*

## Запустите на своих числах

```bash
git clone https://github.com/xniperbuilds/burnrate
cd burnrate/plugins/burnrate/skills/burnrate/scripts
python burnrate.py --days 30
```

Python 3.8+, только стандартная библиотека — без `pip install`, без Node, без shell-инсталлятора, без `curl | bash`. Одинаково работает в Windows, macOS и Linux.

Он читает транскрипты, уже лежащие у вас на диске (`~/.claude/projects/**/*.jsonl`), и выводит:

- вашу разбивку токенов, сырую и взвешенную
- какие инструменты кладут в контекст больше всего объёма и каков их средний размер результата
- какие файлы вы читаете снова и снова
- какие файлы настолько велики, что в одиночку доминируют в сессии
- нагрузку от изображений и бинарных файлов — отдельно и честно

```
  [HIGH] 94 файл(ов) прочитаны 5+ раз
      Повторное чтение тех же неизменённых файлов стоило примерно
      2,4 млн токенов сверх первого чтения (прибл.). Худший:
      project-notes.md (107 раз).
      -> Их перечитывают, потому что содержимое не удержалось в контексте.

  [HIGH] Read даёт 50% всего, что возвращается в контекст
      3 100 вызовов вернули ~4,5 млн токенов; в среднем 1 400 токенов
      на вызов, крупнейший единичный результат ~16 800 токенов.
      -> Читайте с offset/limit, а не файлы целиком.
```

## Что загружается ещё до того, как вы что-то напечатали

```bash
python burnrate.py --startup
```

Стартовый контекст оплачивается на **каждом ходу каждой сессии**, поэтому это самое рычажное знание. Реальный вывод:

```
-- ИЗМЕРЕНО (первый оплачиваемый ход каждой сессии) -------------
  медиана стартового контекста    60 057 токенов   по 310 сессиям
  Он пересылается как cache_read на ВСЕХ последующих ходах.

-- АТРИБУТИРОВАНО (скан вашей конфигурации, прибл.) -------------
  описания скиллов                      12 998  105 скилл(ов)
  CLAUDE.md (пользовательский)           3 674
  индекс памяти (MEMORY.md)              2 718  лимит 200 строк / 25 КБ
  описания субагентов                    1 258  18 агент(ов)
  итого атрибутировано                  20 648

  неатрибутированный остаток            39 409  системный промпт + схемы инструментов
  ваша доля                               34,4%  это то, что можно урезать
```

Три вещи отличают это от оценщика конфигурационных файлов:

- **Измеренное** число точное — оно берётся из поля `usage`, а не из подсчёта слов.
- **Остаток** показывается, а не прячется. Две трети этой стартовой стоимости — системный промпт и схемы инструментов, которые не изменятся, сколько бы вы ни правили свои файлы. Сказать об этом — значит избавить вас от оптимизации числа, которое вы не можете сдвинуть.
- Для скиллов и агентов считается **только frontmatter**. Их тела загружаются по требованию, поэтому подсчёт целых файлов скиллов — как обычно делают инструменты, сканирующие каталоги конфигурации, — завышает стартовую стоимость в несколько раз.

Обычный сюрприз: **установленные, но неиспользуемые скиллы весят больше, чем `CLAUDE.md`.** Описание каждого скилла загружается на каждом ходу независимо от того, вызываете вы его или нет, поэтому `--startup` называет самые тяжёлые поимённо.

## Докажите свою экономию

```bash
python burnrate.py --snapshot before
#  ... что-нибудь измените ...
python burnrate.py --compare before
```

`--compare` показывает **средние значения на ход**, чтобы более загруженная неделя не выглядела регрессом:

```
                                              было     сейчас  изменение
  cache write (новый контекст)                8.6K       5.9K    -31,7%
  cache read (пересылка каждый ход)          213.3K     219.5K      2,9%
  вывод (что написал агент)                    1.4K       1.4K      1,3%

  с учётом стоимости, на ход                  39.1K      36.4K     -6,9%

  Это ваше измеренное изменение. Это не утверждение о чьём-то ещё.
```

## Установить как скилл

```
/plugin marketplace add xniperbuilds/burnrate
/plugin install burnrate@xniperbuilds
```

После установки он делает три вещи: сначала измеряет, потом рекомендует; применяет дисциплину контекста, нацеленную на дорогие 83–99%, а не на дешёвые 0,6%; и измеряет снова, чтобы улучшение было фактом. Полный сборник сокращений — упорядоченный по влиянию, с указанием цены каждого — в [`references/cuts.md`](../../plugins/burnrate/skills/burnrate/references/cuts.md).

## Чего он не сделает

- **Не заставит вашего агента говорить странно.** Телеграфный стиль срезает малую часть счёта и усложняет проверку результатов.
- **Не выдаст вам среднее.** Только ваши измеренные числа.
- **Не скроет собственную стоимость.** При вызове этот файл тоже попадает в контекст. В коротких сессиях эти накладные расходы могут превысить экономию — и `--compare` честно вам это покажет.
- **Не обменяет корректность на токены.** Краткость касается того, что передаётся, но никогда — рассуждений, тестов и дословного текста кода и ошибок.

## Известные ограничения

- Суммы токенов берутся из поля `usage` и точны. Объём результатов инструментов пересчитывается как ~4 символа/токен и везде помечен как приблизительный.
- Изображения и PDF тарифицируются по размерам, а не по символам. Они считаются отдельно и никогда не переводятся в число токенов.
- Взвешивание по стоимости использует опубликованные соотношения между классами токенов, а не цены по моделям — взвешенная колонка это доля, а не сумма денег.
- Подписочные тарифы могут взвешивать использование иначе, чем API-тарификация. Именно поэтому приводятся обе доли; ни одна не подаётся как счёт.
- Виден только локальный транскрипт. Работа на другой машине или в браузере не учитывается.
- Корпус выше — это 348 сессий одного активного пользователя. Это свидетельство, а не всеобщий закон — и в этом весь смысл. Запустите на своих.
